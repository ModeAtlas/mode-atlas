# Mode Atlas 3.0.0 implementation and evidence

This release addresses parts of the independent review dated 22 October 2026; it
does not complete all of its required actions. The user's
corrections are requirements: retain coin purchase placeholders; Home is the
whole-app and personal overview; Learn is the extensible branch directory; Kana
contains only Kana learning. First-time learners receive a different experience,
not the returning dashboard with empty counters.

## Research decisions

NN/g's [progressive disclosure](https://www.nngroup.com/articles/progressive-disclosure/)
supports showing the essential task first with advanced controls available on
request. It does not justify hiding the existence of those controls or forcing
experienced learners through a beginner route.

The Japan Foundation's [Irodori approach](https://www.irodori.jpf.go.jp/en/about.html)
connects language knowledge to concrete everyday outcomes, context and listening.
This release adds original practical learning sequences; it does not copy
Irodori lessons or claim that character recall is communicative proficiency.

Learning state is based on evidence in existing saves. Consent, account creation,
tour completion and visiting a page do not demonstrate learning. An unsuccessful
attempt still demonstrates participation; it must not disappear from the habit
model, and it must not create competitive earnings.

## Verification boundaries

Automated tests, local browser checks and source review are evidence of those
checks only. Real learner studies, a Japanese educator's independent review,
physical-device notification delivery and production Firebase configuration need
their own evidence. They will be reported separately, never fabricated or used
as a reason to indefinitely withhold the 3.0.0 implementation.

## State, event and migration contracts

- `ModeAtlasLearningExperience.snapshot()` reads learning evidence only. New means
  no learning and no started lesson; starting means a lesson was entered without
  an attempt; returning includes unsuccessful attempts, saved words, handwriting,
  Kanji evidence and restored legacy correct/review data. These presentation states
  do not unlock content, grant XP or confer proficiency.
- `ModeAtlasProgress` version 8 owns study-day participation. New word/handwriting
  receipts are bounded to five distinct IDs per branch per local day. Merge is an
  ID union. Existing earned totals and legacy correct counts remain supported.
- Kanji schema 2 stores at most 16 recent independent events per character/skill
  across devices, with the newest 12 used for readiness. Source counters still
  merge independently. Version-1 migration preserves previously earned milestones
  under the old rule without inventing recent successes.
- `ModeAtlasStorage.transaction()` remains the answer durability boundary. The
  journal is committed before values, replay is idempotent, and a new transaction
  first finishes any pending transaction. Large JSON patches have before/after
  checksums and bounded operations; mismatched recovery data is retained and raises
  an error instead of being silently discarded.
- `modeAtlasProgressChanged`, `modeAtlasWordsChanged` and
  `modeAtlasCloudDataChanged` notify projections after owner writes. The learning
  owner, not a page's rendering code, grants habit credit. Account-change events
  invalidate open learning dialogs, buffered rewards and delayed interface results.
- Verified sessions live under the UID and require server-issued ID/token/seed,
  configuration, start and expiry. Client-visible seeds do not hide answers.
  Personal practice proceeds if authorization fails; unissued/expired/legacy
  reward outboxes cannot mint new currency. Server completion and daily budgets
  remain separate from the editable personal save.
- Backups whitelist nine learning sections and check ownership at preview and
  execution. Restore is an explicit replacement of listed sections using the
  existing reset/import generation boundary; empty sections are not erased merely
  because an exported envelope contains them. They are not a wallet or Auth backup.
- Cloud transport permits at most 32 part references, each at most 120,000
  characters. The shared decoder's 16 MiB cap is an additional ceiling, not a
  promise that browser local storage has that much free capacity.

## External validation protocol (prepared, not performed)

1. **First session:** recruit beginners, rusty learners and existing learners with
   consent. Give an empty installation or their restored fixture. Ask: “Choose
   something useful to learn and finish a short session.” Do not point at the
   intended control. Record first action, wrong turns, assistance, completion and
   the participant's explanation of progress, mastery and streaks. Then ask them
   to find saved words and an advanced practice option. Keep observations separate
   from suggestions. This task has not recruited or messaged anyone.
2. **Delayed learning:** use a reviewed subset of the new vocabulary. Record an
   unaided baseline, teach once, and test after roughly one and seven days. Include
   a new sentence/context using the learned expression. Score recognition, typed
   reading and appropriate use separately; record exposure between checks. Do not
   market a small convenience pilot as an efficacy study.
3. **Educator review:** review all 30 original words/examples/translations and the
   six application questions. Sample every Kanji band and every supplemented
   dictionary selection rule; prioritize beginner ambiguous readings and acceptable
   English alternatives. Log entry ID, issue, accepted answer, source and decision.
   The eight isolated-reading entries are identified in the coverage JSON. Their
   disclosure does not substitute for independent review.
4. **Two-device durability:** on separate signed-in devices make different offline
   word edits and Kana/Kanji attempts; reconnect in both orders and concurrently.
   Compare detailed evidence, summaries and last answer, then interrupt a write,
   nearly exhaust storage, restore a backup and switch accounts during an upload.
   Verify privacy and no lost/repeated contribution without resetting away defects.
5. **Physical-device/operations:** on a modest iPhone and iPad measure median/p95
   input-to-feedback, save and route-start timings with a mature fixture. Exercise
   VoiceOver, larger text, IME, normal/slow audio, sign-in/linking, notifications,
   widget account cleanup and local midnight. Record device/OS/build, not just a
   generic “iOS passed”. In the actual Firebase project verify deployed rules,
   provider/enforcement status, IAM, retry cleanup, TTL, alerts and quotas. Keep
   production credentials and private notes out of evidence exports.

## Current verification record

- Release build, ownership/security audits, native web packaging and Python tests:
  passed. JavaScript tests: **267 passed**.
- Auth/Firestore/rules/service emulator suite: **83 passed**; the expanded security
  suite then passed **5 tests**, adding timing-hold and early-daily-completion cases
  (85 distinct backend cases covered across these runs).
- Browser: the full **722-case** run passed 717; all five failures were corrected
  and passed on rerun. The final **84-case acceptance pass** includes the new
  Settings restore dialog (two additional desktop/mobile cases), first-use,
  all-route large-text coverage, Word Bank and smoke tests. Final backup ownership
  changes passed a further **4-case** run. This is **724 distinct browser cases**
  verified across the full run and targeted reruns, not a claim that a single
  724-case invocation ran on the final tree.
- The five final full-run failures were four stale lesson-button expectations and
  an incompletely initialized sign-out fixture. The latter now models an actual
  prior owner, waits for auth initialization and verifies the native snapshot
  contains that owner's activity before testing sign-out suppression.
- Fresh/returning desktop and phone screenshots were inspected. New Kana shows
  one primary learning action, with experienced tools disclosed separately.
- Full local Functions callable/trigger startup: blocked at local Firestore
  Eventarc registration, reproduced with loopback proxy exclusion. No callable/
  trigger pass is claimed for this environment.
- Native compilation/signing, physical devices, live deployment and human studies:
  not executed in this environment. Their protocols and migration steps are
  concrete in `development-3.0.0.md` and above.
