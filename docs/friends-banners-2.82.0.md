# Friends and profile banners — 2.82.0

The same canonical UI, reward policy and account model serve web and iOS.

## Ownership and layout

`mode-atlas-social-ui.js` owns Friends and the staff hub inside the existing
account navigation panel. The home toolbar contains the list selector, Add
friend, My code, Refresh and one staff-only shield. Pending requests keep their
visible shortcut. The hub replaces the panel content with Reports, Warnings,
Team (moderators) and Restricted tabs; it does not stack another dialog. Confirmations
return to the originating staff section.

`mode-atlas-social.css` owns shared spacing and responsive layouts. Controls retain
44px minimum height; large text wraps naturally. Official badges share the name
line where space allows. The existing account panel owns scrolling.

`mode-atlas-reward-rules.js` owns Original plus six milestone banners at levels
1, 5, 10, 20, 35 and 50. `mode-atlas-progress.js` stores banner/bannerAt alongside
landmark/at in the existing appearance object. They merge independently, so a
frame choice on one device cannot discard a newer banner choice from another.
Legacy saves default to Original. Changing appearance does not award XP.

`mode-atlas-rewards.css` owns the decorative gradients, using the existing
milestone/theme tokens. The compositional banner layer does not replace card
background or text colours. Profile, Your Atlas, Friends, rankings and profile
previews consume it. `projection.cjs` validates the banner against the shared
level policy before adding it to the public social projection. The server copy
of policy is generated by `build_social_backend.py`.

`mode-atlas-diagnostics.js` maps canonical screen identities to user-facing names
for feedback; `mode-atlas-head-bootstrap.js` resolves both clean web paths and
bundled filenames. Optional technical diagnostics remain explicitly opt-in.

## Staff permissions

`staff.cjs` remains the authority for role and protected-target checks. Staff
can read the moderator roster; only Admin can change it. `moderation.cjs` lists
at most 20 warning records per page, rechecks the caller and target roles inside
a transaction, and excludes deleted/cleared accounts. List responses include
name, count, date and role, without warning text, author, email or private saves.
Detailed warning history remains behind the existing staff action.

Admin can clear warnings and act on official accounts. Moderators cannot clear
warnings or act on Admin, other moderators or themselves. Revoked/restricted
moderators lose access even if the client still displays an older hub. Warning
history continues to survive leaving Friends and is removed on account deletion.

## Rollout

Public version 2.82.0; iOS build 2080002. Deploy the backward-compatible social
backend before publishing the updated website or distributing the new app:

```sh
npm run social:install
npm run build:social
npm run social:deploy
npm run social:status
```

Use `npm run social:login` first if this Mac is not signed in to Firebase. No new
Firebase index, Apple capability or App Group setting is needed. Existing saves
gain their public banner when their normal progress sync updates the projection.
Update both clients when testing cross-device appearance changes.

Verify a normal account sees no staff icon; Admin and Moderator can open each
hub section with the correct actions. Select an unlocked banner in Your Atlas
→ Rewards, change the frame separately, sync, and view it from a second account.
Check narrow layouts and large text, plus Feedback from Kana and both practices.
